# M0031 — Sprint 3.1: Claude Vision Provider

> Status: **Complete** (2026-07-13) · Branch: `sprint-2a-upload-batch`
> The first REAL AI provider — playground-only; the audit workflow still makes
> zero AI calls.

## What Shipped

- **`ClaudeVisionProvider`** (`services/ai/providers/claude/`) implementing the
  existing `AIProvider` interface unchanged. Everything Claude-specific stays inside
  the adapter: the `@anthropic-ai/sdk` dependency, model ids
  (`claude-sonnet-5` default, `claude-haiku-4-5` for cost comparison), the 5 MB /
  JPG-PNG-WEBP image constraints, markdown-fence stripping, and SDK error shapes.
- **Factory integration**: `getAIProvider("claude")` returns the adapter;
  `ANTHROPIC_API_KEY` (optional env) is injected there. A missing key fails
  gracefully at call time with a friendly `AI_AUTH` message — browser-verified.
- **Prompt from the registry**: the system prompt is loaded from
  `logbook-extraction/v001` (the versioned artifact) — no prompts in TypeScript.
  Temperature 0. Every response is validated with the canonical Zod schema;
  malformed model output becomes a structured validation failure (raw preserved),
  never an exception or a UI leak.
- **Cost tracking in the response**: provider-reported input/output tokens ×
  a published-price snapshot (`PRICE_PER_MTOK`, marked for extraction into
  versioned config with `AiUsageRecord`), plus measured latency — all rendered by
  the playground. No database persistence yet, per scope.
- **Error mapping** to friendly messages: missing/rejected key, rate limiting
  (429), provider outage (5xx/529), timeout (60 s), unsupported image type (HEIC
  called out explicitly), oversized image — the last two rejected _before_ spending
  a request.
- **Playground**: Claude is now selectable; OpenAI/Gemini/Azure remain disabled and
  server-rejected.

## Testing

11 new tests (suite: **63 green**), Anthropic SDK fully mocked — no real API calls,
fully deterministic: canonical translation + cost math, fence stripping, malformed
output → validation failure, graceful no-key, pre-flight image rejections, and the
full HTTP error-mapping table.

**War story worth keeping:** five error-mapping tests failed mysteriously with raw
errors despite correct mapping. Root cause: `beforeEach(() => mock.mockReset())`
_returns the mock function_, and vitest treats a function returned from `beforeEach`
as a teardown callback — so vitest itself invoked the throwing mock during cleanup.
Fix: braces. Recorded here because it will bite again.

## Explicitly Not Done

No audit-workflow integration (playground remains the only entry point), no OCR
pipeline, no `OcrResult`/`AiUsageRecord` persistence, no CRM, no matching, no other
providers. Prompt v001 remains a DRAFT pending real logbook samples — the first
production-representative Claude run should happen in the playground the day samples
arrive.
