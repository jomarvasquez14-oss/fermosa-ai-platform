# M0050 — Production CRM Dataset Builder

> Status: **Complete** (2026-07-14) · Branch: `feature/crm-browser-connector`
> Expands the M0045 dataset generator into a production sweep tool: real
> patient enumeration (branch / date-range / entire-clinic), a
> reproducibility seal per patient, progress + ETA, hash verification, and
> duplicate detection — all read-only, resumable, and idempotent. Introduces
> **ADR-037** (additive patient enumeration on the connector seam).

## What shipped

### Additive enumeration on the connector seam (ADR-037)
`CRMConnector` gains an **optional** `listPatients(page, options?): Promise<PatientPage>`
— a deliberate read-only listing distinct from `findPatients` (a search). Optional so
the seam extension weakens nothing: a connector that cannot enumerate omits it, and
the builder fails loudly rather than sweeping nothing. The **mock** connector
enumerates its fixtures a fixed page at a time (3/page → the 9-fixture set is 3 pages),
so every sweep mode runs deterministically offline. The **Playwright** connector reads
the unfiltered `/clients` list page by page, bounded by `maxEnumerationPages`, never a
full unbounded crawl in one call (live-only — no multi-page list capture exists to
replay).

### Sweep modes with DERIVED branch/date membership
The live patient list cannot filter by branch or treatment date server-side
(CRM_DISCOVERY §1). So sweeps enumerate, retrieve, and filter **from the record's own
contents**:

| Mode | Ids from | Filter | `metadata.branch` |
| --- | --- | --- | --- |
| `patient` | `--crm-id` (repeatable) | none | null |
| `all` | enumeration | none | null |
| `branch` | enumeration | keep patients with a treatment at `--branch` | the branch (genuinely applied) |
| `dateRange` | enumeration | windowed retrieval; keep patients with any in-window content | null |

This **supersedes M0045's null-stamp stopgap** (the cherry-picked
"never stamp an unapplied branch" fix): `branch` mode now genuinely applies the branch
as a derived filter, so stamping it is a true provenance claim — while `patient` /
`all` / `dateRange` still never stamp a branch, preserving the stopgap's invariant.

### On-disk layout (mode-scoped)
```
<out>/crm/patient/<crmId>/
<out>/crm/all/<crmId>/
<out>/crm/branch/<branch-slug>/<crmId>/
<out>/crm/date/<from>_<to>/<crmId>/
```
Each patient directory holds `patient.json`, `treatments.json`, `invoice.json`,
`activity-log.json`, **`snapshot.json`**, and `metadata.json`; each dataset root holds
one `manifest.json`.

### `snapshot.json` — the reproducibility seal
The full `NormalizedCrmPatientRecord` plus both hashes from the snapshot engine
(ADR-035): `contentHash` (full record, tamper seal) and `evidenceHash` (business
sections only). `--verify` re-hashes every stored record against the seal it carries
and against `metadata.json`, so a byte-level tamper of any file surfaces as a
content/evidence/metadata hash mismatch. Verify **never contacts the CRM**.

### Operability
- **Progress + ETA** to stderr (enumeration counter, then `retrieving n/N (ETA …)`),
  wired through an `onProgress` callback the generator emits — the core stays pure.
- **Duplicate detection**: identical record content (same `contentHash`) under two
  crmIds is recorded in `manifest.duplicates` and warned.
- **Export summary**: `manifest.summary` (included / skipped / failed / totalBytes),
  echoed by the CLI.
- **Resumable + idempotent + failure-isolated** (preserved from M0045): a patient with
  existing `metadata.json` is skipped on `--resume`; any per-patient error (AppError or
  plain fs Error) is recorded and the batch continues; nothing is swallowed.

## Read-only guarantee
Only `listPatients` / `fetchPatientRecord` are ever called — no mutating route. The CLI
announces the active connector at startup so a bare `pnpm dataset:crm` never silently
sweeps the live CRM.

## Honest costs (documented, ADR-037)
Because branch/date are derived, an "entire branch" sweep must enumerate and retrieve
the **whole clinic** to filter — expensive for large clinics, where an explicit
`--crm-id` list is preferred. Progress/ETA and resumability make a full sweep tolerable
and restartable. The Playwright enumeration re-navigates and advances per page
(the DataTable pagination is a UI control, not a trustworthy URL param), so deep pages
cost more; the `maxEnumerationPages` bound caps it.
