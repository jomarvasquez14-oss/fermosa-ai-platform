# M0040 — Version 0.6.1: Engineering Excellence

> Status: **Complete** (2026-07-14) · Branch: `chore/v0.6.1-engineering-excellence`
> No new business features — CI, observability, developer experience, and
> three formal reviews, preparing the platform for OCR/CRM integration.

## 4.0A — Continuous Integration

`.github/workflows/ci.yml`: push + PR → install (pnpm store cached via
setup-node) → typecheck → lint → migrations against a **Postgres 16 service
container** → full test suite (unit + DB integration) with a step-summary
table → production build. Fail-fast, 20-minute timeout, per-ref concurrency
cancellation. Closes the M1 carry-over ("CI on every push"). PROJECT_RULES 16
updated: the gates are now machine-enforced.

## 4.0B — Observability (`lib/telemetry/`, ADR-032)

Interfaces only, no vendor: structured `Span`s through a `TelemetrySink`
(default sink = the existing logger; broken sinks can never break the
workflow they observe), **correlation ids** via AsyncLocalStorage (audit runs
correlate every stage, rule evaluation, and log line by job id), `trace()` /
`startSpan()` helpers, and **error classification** (AppError code →
subsystem: validation/authorization/crm/ai/storage/…). Instrumented:
orchestrator stage timing (`orchestrator.stage` with attempt + outcome), job
completion totals, and rule-engine timing (`rules.evaluate` with entry/finding
counts and risk score). 6 new tests.

## 4.0C — Developer Experience

`docs/DEVELOPER_GUIDE.md` (setup → database → seeding → branch/commit/release
workflow → tests → CI → observability) and two scripts: `pnpm verify`
(typecheck ∧ lint ∧ test) and `pnpm release-check` (verify ∧ build), both
fail-fast — identical to CI by construction.

## 4.0D — Performance Review → [PERFORMANCE.md](../PERFORMANCE.md)

Measured: bundle table (largest first-load 209 kB on the submission editor;
shared 102 kB), rule engine (1,000 entries < 300 ms, CI-enforced),
orchestrator run profile (~2 s, mock-delay dominated), query counts
(~6–8/stage transition; no N+1s found). Ranked bottlenecks — inline pipeline
execution is #1 and is exactly what OCR integration's job runner addresses.
No optimization performed (none warranted).

## 4.0E — Security Review → [SECURITY.md](../SECURITY.md)

Rule-by-rule verification with structural greps. **One real gap found and
fixed**: the CRM placeholder page lacked its server guard (`requireUser` added
— every `app/(app)` page now grep-verifiably guarded). Risk register: rate
limiting and secret rotation are the two blockers before any shared
deployment; PII/provider-retention sign-off remains the OCR gate.
