# M0035 — Sprint 3.5: Audit Findings Engine

> Status: **Complete** (2026-07-14) · Branch: `feature/audit-findings-engine`
> The canonical output format, built before any producer exists — so no producer
> can invent its own. Mock data only; no rule engine, OCR, CRM, or AI changes.

## What Shipped

- **`AuditFinding` domain model** — persisted (migration
  `20260713163129_audit_findings`), owned by the submission aggregate, never
  hard-deleted. Categories (11 discrepancy kinds grounded in the CRM reference
  study — missing-in-CRM, missing invoice, record edited/deleted, …), severities
  (INFO→CRITICAL), sources (rule engine / CRM discovery / OCR / AI / manual),
  typed Zod-validated evidence references, expected-vs-actual values,
  recommendation, confidence, resolution note. DOMAIN_MODEL.md updated with the
  entity and the §5.5 status state machine; ADR-028 records the decision.
- **Status workflow** — OPEN → REVIEWED → RESOLVED with reopening; resolution
  always passes through review. Transition rules live in one shared function
  (`canTransition`) with the action buttons derived from `nextStatuses` — the UI
  physically cannot offer an illegal transition.
- **Reusable findings kit** (`components/findings/`): severity/status/category/
  source badges, `FindingCard` (collapsed scan row → expanded inspection with
  evidence links into the OCR review screen), `FindingsList` (severity-sorted,
  filterable by severity/status/category), `FindingsSummary` + `rollupFindings`,
  all rendering a serializable `FindingView` — DB rows later, mock now.
- **Route `/findings`** (Auditor + Super Admin; middleware + page guards; Branch
  Managers see no nav item and are bounced) with a labeled mock dataset — one
  finding per category, written as the real producers will write them, aligned
  with the mock CRM fixture scenarios.
- **[docs/VISION.md](../VISION.md)** — the product vision: what v1.0 looks like,
  the auditor's login-to-report day, the branch manager's workflow, the eight
  dashboard KPIs, and how success is measured (business outcomes, product
  health, trust guarantees).

## Verification

- **9 new tests** (suite: **105 green**): transition legality (incl. the
  no-skip rule), `nextStatuses`, evidence schema acceptance/rejection, one-pass
  rollup, severity-then-recency sort, card rendering (collapsed + expanded),
  legal-actions-only buttons, accessible expand toggle.
- Browser-verified (Playwright): 10 mock findings sorted CRITICAL-first,
  severity filter, expanded inspection (expected/actual, evidence with review
  deep-link, recommendation), full status cycle (Resolve → Reopen → Mark
  reviewed) with live summary updates, 375 px with zero horizontal overflow,
  Branch Manager blocked.
- Gates: typecheck / lint / build clean (`/findings` at 5.1 kB).

## What This Unblocks

The rule engine sprint becomes small: compare confirmed OCR data against
`NormalizedCrmPatientRecord`s and **emit findings** — format, workflow, UI, and
dashboard rollups already exist. The findings service layer (persistence,
branch scoping, actor-attributed status changes) ships with that first
producer.
