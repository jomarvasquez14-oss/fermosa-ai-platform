# M002A1 — Sprint 2A.1: Upload Interface

> Status: **Complete** (2026-07-13) · Branch: `sprint-2a-upload-batch`
> Scope: upload **user experience only** — no persistence, no processing.

## Objective

Build the first screen of the audit workflow: a Branch Manager selects an audit date,
stages logbook images (add/preview/rotate/reorder/remove), and presses **Continue**.
Nothing is uploaded or saved — the batch is ephemeral and client-side by design
(ADR-021). This sprint is entirely about the daily-use experience of branch staff.

## What Shipped

- **Route** `/audit/new` (guarded by the new `audit:upload` permission — Branch Manager
  and Super Admin; Auditors don't upload). The Audit landing page gained a
  "New Upload" entry button, shown only to roles that can upload.
- **Reusable upload kit** in `components/upload/`:
  `UploadDropzone`, `ImageCard`, `ImageSorter`, `ImagePreviewDialog`, `UploadToolbar`,
  `UploadRejections`, plus pure validation (`validation.ts`) and types.
- **Batch state hook** `hooks/use-image-upload.ts` — owns object-URL lifecycle,
  validation dispatch, rotation, ordering.
- **Feature screen** `features/audit/components/new-upload-screen.tsx` — composes the
  kit with the audit-date field and Cancel/Continue navigation.
- **Test infrastructure** (first in the repo): Vitest + React Testing Library
  (ADR-022); 25 tests over validation rules, hook behavior, and `ImageCard`.

## UI Decisions

| Decision                                                                | Rationale                                                                                                                                                                                              |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Native `<input type="date">`                                            | Free keyboard support and each platform's own touch picker (iOS wheel, Android calendar); no calendar dependency. Max = today.                                                                         |
| Cards in a responsive grid (1/2/3/4 columns) with explicit Move Up/Down | Predictable, accessible reordering that works identically with touch, mouse, and keyboard; drag-to-reorder deferred as an enhancement.                                                                 |
| Rotation is CSS-only, persisted per image in batch state                | Spec forbids editing; preview and thumbnail stay consistent. Rotation metadata is available to send to the server in 2A.2.                                                                             |
| HEIC accepted, best-effort preview                                      | Browsers that can't decode HEIC (Chrome/Edge) show a "preview not supported" card and the file stays in the batch — rejecting valid files because of a _browser_ limitation would punish iPhone users. |
| Per-file rejection, never per-selection                                 | A 21-file selection with one PDF adds 20 images and explains the one rejection in a dismissible `role="alert"` list.                                                                                   |
| Sticky bottom action bar on mobile, inline on desktop                   | Continue is always thumb-reachable during long batches; 48px touch targets on mobile (44px+ everywhere: icons `size-11`, inputs `h-11`).                                                               |
| Continue shows an honest "nothing was saved yet" toast                  | Placeholder-honesty principle — no fake success before 2A.2 exists.                                                                                                                                    |
| Duplicate detection = name + size + lastModified                        | Catches "picked the same photo twice" without main-thread hashing of 10 MB files.                                                                                                                      |

Limits enforced client-side: **10 MB/file, 20 images/batch**, JPG/JPEG/PNG/HEIC only.

## Explicitly NOT Implemented (deferred by scope)

No backend upload logic, no file saving, no database records, no Upload Batch entity,
no OCR, no AI, no CRM, no storage provider, no API routes. `handleContinue()` is the
single integration point awaiting 2A.2.

## Future Integration Points

1. **`handleContinue()`** in `new-upload-screen.tsx` → will call a 2A.2 server action
   that creates the upload batch (audit date + ordered files + rotation metadata) via
   the service layer, then emits `logbook.uploaded` events.
2. **`validation.ts`** is pure and environment-free → reuse the same rules server-side
   in the 2A.2 action (client validation is UX, not security — PROJECT_RULES 6).
3. **`UploadImageItem.rotation`** → server can apply real rotation at processing time.
4. **`audit:upload` permission** and the `/audit/new` guard are already real; 2A.2 adds
   branch scoping at the service layer when records are created.
5. Progress/retry UI states will slot into `ImageCard` (status badge area reserved).
