# M0061 — Structured Logbook Intake (Excel/CSV)

> Status: **Complete** (2026-07-15) · Branch: `feature/crm-browser-connector`
> A **typed** path from the daily logbook into the platform, parallel to OCR and
> behind the SAME `ConfirmedEntry` seam. Branches fill a spreadsheet instead of
> (or alongside) a photo; the transaction data reconciles against the CRM with
> **no API key, no network, no PII leaving the building**. ADR-041.

## Why

OCR needs an Anthropic API key + a no-retention/DPA sign-off, and its handwriting
accuracy is unproven on messy pages. For the data the audit actually compares
against the CRM, **typed input is ~100% accurate and effectively free** — we just
read the columns. The platform's swappable input seam already accepts a
`ConfirmedEntry[]` regardless of source, so typed data flows through the exact same
matching + deterministic rule engine.

## What it adds

| Piece | What |
| --- | --- |
| **Intake schema (contract)** | `services/intake/logbook-intake-schema.ts` — one Zod schema is the single source of truth for BOTH the CSV headers and the parser (`TRANSACTION_HEADERS`, `SUMMARY_HEADERS`). Mirrors the OCR field vocabulary (services/meds+amounts, cash/bank, points BP/OP/NP). |
| **CSV reader/writer** | `services/intake/csv.ts` — in-repo, RFC-4180-ish (quoted fields, embedded commas, `""` escapes, CRLF). **No new runtime dependency.** |
| **Parser (pure)** | `services/intake/logbook-intake.ts` — `parseTransactions()` groups rows sharing `(date, branch, lineNumber)` into one client (a client spans several service lines, like the paper page), then **down-maps to `ConfirmedEntry`** with the ADR-040 convention (primary service → treatment, staff → therapist, timeIn → time). Keeps a richer `StructuredEntry` (all services/meds/amounts, cash/bank, points) for the later tally. `parseSummary()` parses the daily rollup. Errors are returned as `issues`, never thrown. |
| **`intake:template`** | `scripts/make-intake-template.ts` — writes `templates/logbook-intake/`: blank + worked-example `transactions`/`daily-summary` CSVs and `INSTRUCTIONS.md`. Example is synthetic (July 9 Makati shape) — safe to commit. |
| **`intake:check`** | `scripts/intake-check.ts` — parses + validates a filled sheet and prints the resulting `ConfirmedEntry[]` + captured detail + summary. The offline, deterministic proof that a typed sheet plugs into the pipeline. |

## Verification

- **Unit:** `services/intake/csv.test.ts` (7) + `services/intake/logbook-intake.test.ts` (10) —
  quoted/embedded-comma CSV, CRLF, no trailing-empty-row; multi-service grouping →
  one `ConfirmedEntry` (Rosendo's 3 services); blank → null; `₱`/comma amount
  stripping (`₱800`→`800`, `1,549`→`1549`); non-numeric `lineNumber` and missing
  required column surface as issues; a continuation row with a mismatched client
  name is flagged; full summary round-trip incl. every declared header.
- **End-to-end (no key, offline):** `pnpm intake:template` wrote the five files;
  `pnpm intake:check templates/logbook-intake/transactions.example.csv --summary templates/logbook-intake/daily-summary.example.csv`
  printed 3 clients (Espina / Rosendo / Eusebio) with the correct down-mapped
  treatment/therapist/time, Rosendo's three services grouped under one entry, the
  full daily summary, and **"No issues"**.
- Full `pnpm release-check` green (typecheck + lint + tests + build). No runtime
  dependency added (CSV reader is in-repo).

## Scope / contracts

No DB change, no CRM change (still read-only), no rule-engine change, no frozen
contract touched. Explicit follow-ons: (1) a **web upload UI** + making a
spreadsheet a first-class live `AuditSubmission` source; (2) wiring the daily-summary
totals and the richer transaction fields into the comparison rules (the deferred
financial tally, same boundary as ADR-040); (3) OCR **spot-check** of typed data
against the original photo, once live OCR accuracy is known. The paper logbook stays
the contemporaneous evidence; typed intake is the fast, accurate everyday path.

See [INTAKE.md](../INTAKE.md) for the two-path model and the CSV format.
