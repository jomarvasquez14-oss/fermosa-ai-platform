# M0030 — Sprint 3.0: AI Playground

> Status: **Complete** (2026-07-13) · Branch: `sprint-2a-upload-batch`
> First implementation on the AI seam — mock provider only, zero external calls.

## Objective

An internal developer tool (Super Admin only) to test OCR providers, models, prompt
versions, and JSON outputs through the exact `AIProvider` seam production will use —
before any real provider integration exists. Deliberately decoupled from the Audit
Module; nothing is persisted.

## Design Notes

- **Mock models select behavior**, mirroring how real model choice changes outcomes:
  `mock-clean` (high confidence), `mock-messy` (low-confidence fields + unreadable
  regions — exercises the §5 review bands), `mock-malformed` (schema-violating JSON —
  exercises the validation-error display). Deterministic per image bytes, simulated
  latency and token/cost figures, so every UI state is reachable on demand.
- **The playground displays what production will persist**: raw provider response
  (future `OcrResult.rawText`), parsed extraction, per-field confidence badges colored
  by the OCR_ARCHITECTURE §5 bands, validation issues with field paths, latency,
  tokens, and estimated cost.
- **Prompt v001 is a DRAFT** — the assumed patient/treatment/therapist/time columns
  remain gated on real logbook samples (OCR_ARCHITECTURE §11.1). The registry
  (`PROMPT_VERSIONS`) makes prompt rollout an explicit, reviewable code change.
- `AI_PROVIDER` env now includes and defaults to `mock`. The four real providers
  appear in the catalog as disabled options and still throw `NotImplementedError` at
  the factory.

- Browser-verified via Playwright as Super Admin: clean run (6 entries, band-colored

## What This Unblocks

Sprint 3.x real providers implement the already-exercised contract and appear in the
playground by flipping `implemented: true` — prompt iteration, provider A/B checks,
and cost sanity checks all happen here before a single audit submission touches a
real model.
