# M0053 — Audit Dashboard

> Status: **Complete** (2026-07-14) · Branch: `feature/crm-browser-connector`
> Three role-scoped dashboards built from **real submissions and findings
> only** — no OCR, no mock data. Pure aggregation builders + a role-routing
> service + dependency-free (SVG/CSS) charts, replacing the old placeholder
> stat cards.

## Structure

- `services/dashboard/dashboard-builder.ts` — **pure** builders
  (`buildAuditorDashboard`, `buildBranchDashboard`, `buildAdminDashboard`).
  Deterministic aggregation over already-fetched rows; no Prisma, no
  `Date.now()`, no I/O — same rows in, same model out.
- `services/dashboard/dashboard-service.ts` — Prisma reads (branch-scoped by
  role) + role routing. Reads submissions/findings/branches at rest; **never**
  the live CRM.
- `components/charts/{bar-chart,trend-chart}.tsx` — hand-rolled, no chart
  dependency. Theme-aware (primary/muted tokens, `currentColor`), responsive
  (flex / viewBox), accessible (labelled lists, `role="img"` summaries).
- `features/dashboard/components/*` — the three role views + a `StatTile`.
- `app/(app)/dashboard/page.tsx` — role-switched; Super-Admins also get the
  cross-branch admin roll-up below their auditor view.

## The three views

**Auditor** (Auditor + Super-Admin): pending audits, completed audits, critical
(unresolved) findings, review queue (open findings), average review time
(hours from raised→first-review), completed-audits-per-month bar chart.

**Branch** (Branch Manager, scoped to own branch): audit score, compliance
score, open/resolved findings, monthly compliance-history trend.

**Admin** (Super-Admin): branch ranking table (by compliance, then fewer open
findings), monthly audit-volume trend, finding-trends trend, top recurring
issue categories, average audit duration.

## Scoring (deterministic, documented)

Severity risk weights mirror the rule engine's defaults
(INFO 0, LOW 1, MEDIUM 3, HIGH 7, CRITICAL 15).

- **compliance score** = `clamp(100 − openRiskPoints, 0, 100)`, where
  `openRiskPoints` is the severity-weighted count of **OPEN** findings
  normalized per completed audit (so a busy branch isn't punished for volume).
  A branch with no open findings scores 100.
- **audit score** = share of a branch's submissions that reached `COMPLETED`.

These are product definitions chosen for this milestone; they live in one place
(`dashboard-builder.ts`) and are fully unit-tested.

## Real data + honest empty states

Every number comes from Prisma aggregates over real rows. Nullable metrics
(no reviewed findings yet, no completed audits yet) render as an em dash, and
empty charts show an explicit "No … yet." — never a fabricated zero dressed up
as data. The old `placeholder-stats` mock file and its two components were
**deleted** (the spec: no mock data where real data exists).
