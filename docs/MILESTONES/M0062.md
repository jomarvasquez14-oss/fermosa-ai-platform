# M0062 — Single-Workbook (xlsx) Logbook Intake

> Status: **Complete** (2026-07-15) · Branch: `feature/crm-browser-connector`
> Combines the two M0061 intake sheets into ONE Excel workbook with separate
> **tabs** ("Transactions" + "Daily Summary", plus "Instructions"), because CSV
> cannot hold multiple tabs. Adds `exceljs` and makes `intake:check` read a
> filled `.xlsx` directly; the CSV path still works. ADR-042.

## Why

The owner asked to combine the two templates into one file with tabs — the
natural way branches want to work (one file per day, not two). Sheet tabs are an
Excel-workbook feature that CSV does not have, so this needs the `.xlsx` format
for both writing the template and reading a filled workbook back.

## What it adds / changes

| Piece | What |
| --- | --- |
| **`exceljs` dependency** | `services/intake/workbook.ts` — the ONLY module that touches it. `writeIntakeWorkbook()` writes Transactions/Daily Summary/Instructions tabs; `readIntakeWorkbook()` reads the tabs into `string[][]` grids. Pure numbers are written as numeric cells (no "number stored as text" warning); everything reads back as text. |
| **Grid-based parser cores** | `services/intake/logbook-intake.ts` — `parseTransactionsGrid()` / `parseSummaryGrid()` extracted so a workbook sheet and a CSV go through the **identical** logic (the string entry points now wrap them). |
| **`intake:template`** | Now emits `logbook-intake.template.xlsx` (blank, two tabs) and `logbook-intake.example.xlsx` (filled), plus `INSTRUCTIONS.md`. The four standalone CSV templates are removed (superseded). |
| **`intake:check`** | Accepts a single `<logbook.xlsx>` (both tabs from one file) **or** the existing `<transactions.csv> [--summary <daily-summary.csv>]`. Detected by extension. |

## Verification

- **Unit:** `services/intake/workbook.test.ts` (2) — write→read round-trip through a
  real temp `.xlsx`: two tabs parse back to the right `ConfirmedEntry` (multi-service
  grouping intact, numeric amount `400` round-trips to `"400"`); a workbook missing the
  Transactions sheet is reported as an issue. Existing CSV/parser tests (17) unchanged
  and still green — the grid cores are shared.
- **End-to-end (no key, offline):** `pnpm intake:template` wrote the two workbooks;
  `pnpm intake:check templates/logbook-intake/logbook-intake.example.xlsx` (one file,
  both tabs) printed the 3 clients with correct down-map, Rosendo's three services
  grouped, the full daily summary, and **"No issues"**.
- Full `pnpm release-check` green (typecheck + lint + tests + build).

## Scope / contracts

Intake schema, down-map, CRM connector (read-only), and rule engine all unchanged —
this is purely the file *carrier* (xlsx workbook) plus a shared grid seam. New runtime
dependency `exceljs` (ADR-042, which supersedes the "no new dependency" property of
ADR-041). Follow-ons from M0061 stand: web upload UI, wiring summary/richer fields into
the rules, and OCR spot-check. See [INTAKE.md](../INTAKE.md).
