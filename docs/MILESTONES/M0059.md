# M0059 — OCR Schema v2 (Per-Patient Full) + Prompt v002

> Status: **Complete** (2026-07-15) · Branch: `feature/crm-browser-connector`
> With 189 real logbook photos in hand, the OCR extraction schema moves off the
> assumed 4-field guess to **"per-patient full"** (schemaVersion 2, ADR-040):
> services + amounts, staff, time in/out, cash/bank, meds, points — the shape the
> real logbooks actually carry. Closes OCR_ARCHITECTURE §11.1. Part 1 of 2
> (M0060 builds the extraction + calibration harness).

## Why now

The dataset that blocked OCR is resolved — the user uploaded 189 branch logbook
photos. OCR_ARCHITECTURE §11.1 said *"get real photos before writing prompt v001;
every downstream sprint depends on this shape being right."* The photos show a
richer page than the v1 assumption, and M0056 unlocked the CRM's invoice
payments/amounts — so amounts can now be reconciled on **both** sides. The
scope decision (owner): **per-patient full**, daily financial rollup deferred.

## What changed

| Area | Change |
| --- | --- |
| **OCR schema** | `services/ai/ocr-schema.ts` → `schemaVersion 2`. Entry: `patientName, staff, timeIn, timeOut, sessionNo, cash, bank` (ExtractedField) + `services[]`/`meds[]` (`{name, amount}`) + `points{bp,op,np}`. Page gains `pageType` (`transaction \| summary \| mixed`) so summary-only pages validate with zero entries. |
| **Prompt** | New `logbook-extraction/v002.md` (registered, non-draft) with the real columns; v001 stays frozen. CHANGELOG updated. |
| **Ground truth** | New `services/ai/ground-truth-schema.ts` — the **bare-value mirror** (no confidence; `null` = illegible/absent) — plus `ocr-samples/expected/_TEMPLATE.json` (v2) and a validator CLI **`ocr:gt:check`** (`scripts/validate-ground-truth.ts`). |
| **Consumers (down-mapped, not expanded)** | `matching-executor` maps v2 → the unchanged `ConfirmedEntry` (primary service → treatment, staff → therapist, timeIn → time). OCR review kit (`components/ocr-review/types.ts`) reviews the v2 **scalar** fields. Mock provider + AI playground + all affected tests updated to v2. |

The comparison rules and the review UI's handling of the **array** fields
(services/meds/points) are a deliberate follow-on — the down-map keeps every
existing finding and behavior identical until calibration (M0060) proves the
richer extraction, which is the safe order.
