# M0033 — Sprint 3.3: OCR Review Interface

> Status: **Complete** (2026-07-13) · Branch: `sprint-2a-upload-batch`
> The human-review half of the OCR design (OCR_ARCHITECTURE §5) — built and
> exercised entirely on mock extractions. No AI calls, no CRM, no DB changes.

## What Shipped

- **Reusable review kit** (`components/ocr-review/`): `OCRField` (value +
  confidence + accept/edit/unreadable/undo), `ConfidenceBadge` (band-colored;
  now also the playground's badge — single source), `OCRImageViewer` (zoomable
  original evidence), `OCRReviewPanel` (per-line entry cards), `OCRSummary`
  (progress stats), `OCRNavigation` (page dots + gated confirm), plus the
  band thresholds (`confidence.ts`) and the isomorphic `buildReviewPages`.
- **Review state hook** (`hooks/use-ocr-review.ts`): write-through-ref state;
  ≥ 0.95 readable fields start pre-accepted (§5), model-unreadable fields
  require an explicit human verdict; corrections never overwrite the OCR
  original; confirmed pages freeze; progress is derived, not tracked.
- **Route** `/audit/[submissionId]/review` — `audit:manage` guard (Auditors +
  Super Admins; Branch Managers → forbidden, verified), drafts redirect back.
  Entry point: a "Review OCR" button on submitted-submission views.
- **Mock feed**: the page generates deterministic extractions server-side with
  the existing `MockAIProvider` (`mock-messy`, seeded per image) over the
  submission's real stored images — so the review UI exercises real evidence
  with simulated OCR, clearly labeled ("Preview with simulated OCR",
  PROJECT_RULES 28 placeholder honesty). Confirmations stay client-side.

## Review Rules Implemented

Accept requires a readable value; Edit keeps the OCR original visible
(struck through) beside the correction; Unreadable is an explicit verdict
distinct from the model's flag; Undo returns any decision to pending with the
original value restored. **Confirm is gated on every field being resolved**,
auto-advances to the next unconfirmed page, and freezes the page.

## One RSC lesson recorded

`buildReviewPages` originally lived in the `"use client"` hook module; calling
it from the server page threw at runtime (client function invoked from
server). It now lives in a pure isomorphic module (`build-review-pages.ts`) —
initial state is built on the server, owned by the client hook afterward.

## What This Unblocks

OCR integration (next) swaps exactly one thing: the mock feed becomes
persisted `OcrResult`s, and Confirm becomes a server action writing review
verdicts. The kit, hook, gating rules, and route contract don't change.
