# M0039 — Sprint 3.9: Browser Automation Framework

> Status: **Complete** (2026-07-14) · Branch: `feature/audit-findings-engine`
> FRAMEWORK ONLY: no Playwright dependency, no live-CRM contact. The mock
> driver is the only implementation that exists.

## What Shipped (`services/browser/`, ADR-031)

- **`BrowserDriver`** — the six-method seam the future Playwright adapter
  implements (`goto/currentUrl/fill/click/readText/isVisible/close`);
  **`MockBrowserDriver`** simulates the CRM in memory (aligned with the v1
  selector map) with scriptable failures: session expiry, N network failures,
  CAPTCHA, per-page layout breakage.
- **`SelectorRegistry`** — versioned selector maps (`crm-selectors/v1`, shaped
  by the docs/crm-reference captures: real routes, observed structure).
  Selectors never live in page objects; unknown keys and structural
  **fingerprint** mismatches fail loudly as CRM_LAYOUT naming the selector.
- **Page objects** — `BasePage` + Login / Dashboard / PatientSearch /
  PatientProfile / Invoice / ActivityLog: behavior only, read-only operations,
  fingerprint-validated before use. Login detects CAPTCHAs and stops
  (CRM_CHALLENGE — never bypassed).
- **`BrowserSession`** — login, logout, expiry detection (the
  every-navigation invariant), ONE auto-reconnect, health check; credentials
  in memory only.
- **`NavigationManager`** — navigate → wait → verify → recover; retry only
  transient failures (never captcha/forbidden/layout); navigation history.
- **Policies as data** — `RetryPolicy` / `TimeoutPolicy` with `withRetry` /
  `withTimeout` helpers (timeout → CRM_TIMEOUT).
- **`BrowserManager`** — one manager = one context = one session
  (CRM_DISCOVERY §5); wires driver + registry + session + navigation.
- **`/dev/browser`** (Super Admin): session controls, page navigation with
  history, the selector-registry table, and failure-simulation buttons — every
  recovery path demonstrable without the live system.
