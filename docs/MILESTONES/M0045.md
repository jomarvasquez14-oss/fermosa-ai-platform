# M0045 — CRM Dataset Generator

> Status: **Complete** (2026-07-14) · Branch: `feature/crm-browser-connector`
> A read-only, resumable, idempotent generator that sweeps the `CRMConnector`
> seam into a reproducible on-disk dataset ("Dataset B"). No new architecture,
> no contract changes, CRM never written.

## What shipped

`services/crm/dataset/`:
- `dataset-generator.ts` — `splitRecord` (one normalized record → four sections),
  `metadataFor` (provenance per patient), `generateDataset` (the sweep).
- `dataset-writer.ts` — filesystem I/O; `assertSafeCrmId` guards the patient id
  used as a path segment (rejects `/`, `\`, `..`).
- `manifest.ts` — `DatasetMetadata` / `DatasetManifest` / `GenerateOptions` types.
- `index.ts` — barrel.
- CLI `scripts/generate-crm-dataset.ts`, run via `pnpm dataset:crm -- …`.

## Output tree

```
<outDir>/crm/<crmId>/patient.json
<outDir>/crm/<crmId>/treatments.json
<outDir>/crm/<crmId>/invoice.json
<outDir>/crm/<crmId>/activity-log.json
<outDir>/crm/<crmId>/metadata.json
<outDir>/crm/manifest.json
```

`datasets/` is git-ignored — datasets contain real PII when generated from the
live CRM and must never be committed.

## Guarantees

- **Read-only:** only `fetchPatientRecord` / `findPatients` are ever called; the
  connector contract forbids writes. The generator adds no mutating path.
- **Resumable + idempotent:** with `--resume`, a patient whose `metadata.json`
  already exists is skipped (recorded as a `skipped <id>` warning) and its stored
  provenance is backfilled into the manifest — a fully-resumed run still writes a
  complete, non-empty manifest.
- **Failure-isolated + loud:** any per-patient error (connector `AppError` OR a
  filesystem/path error) is recorded in `manifest.failures` with its code and
  message; the batch continues. Nothing is silently swallowed — every failure is
  in the manifest.
- **Reproducible:** each patient's `metadata.json` carries `snapshotHash`
  (SHA-256 over the canonical record, reusing the snapshot engine's `contentHash`),
  `connectorKind`, `selectorVersion`, and `retrievedAt`.

## Metadata & manifest

Per-patient `metadata.json`: `crmPatientId`, `connectorKind`, `selectorVersion`,
`retrievedAt`, `snapshotHash`, `crmVersion`, `branch`, `window`.

`manifest.json`: `generatedAt`, `connectorKind`, `selectorVersion`, `patients[]`,
`pageCount`, `retrievalDurationMs`, `failures[]`, `warnings[]`.

> **`crmVersion` proxy:** the CRM exposes no version string, so `crmVersion` uses
> the selector-map version (`selectorVersionOf(sourceRef)`) as the closest
> reproducibility anchor — documented in code and here.

## ⚠ Operational note — the CLI reads the CONFIGURED connector

`pnpm dataset:crm` uses whatever `CRM_CONNECTOR` selects. On a machine whose
`.env` sets `CRM_CONNECTOR=playwright` (as this one does for live validation),
**the CLI hits the live CRM** (read-only). The CLI now prints the active
connector at startup (`CRM connector: browser-automation — LIVE CRM (read-only)`)
so this is never silent. For a fixtures-only dry run, set `CRM_CONNECTOR=mock`.
This is by design — the tool exists to pull Dataset B from the real CRM — but
operators should know a bare invocation is a live sweep.

## Modes

`--mode patient` (one `--crm-id`), `--mode branch` (`--branch`), `--mode
dateRange` (`--from`/`--to`), `--mode all`. Non-`patient` modes resolve ids via
`findPatients` (a read-only sweep); over the mock connector these yield limited
results (the mock has no full directory), which is expected — the live connector
performs real sweeps.
