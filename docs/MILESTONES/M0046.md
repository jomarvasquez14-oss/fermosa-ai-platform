# M0046 — Audit Report Generator

> Status: **Complete** (2026-07-14) · Branch: `feature/crm-browser-connector`
> Reproducible audit reports (HTML, PDF-ready HTML, JSON) built ONLY from stored
> evidence — submission + findings + snapshot metadata. No live CRM after the
> snapshot exists; no new architecture; no contract changes.

## What shipped

`services/report/`:
- `report-builder.ts` — **pure** `buildReportModel(input)`: assembles `ReportModel`
  (executive summary data, timeline, finding/severity summaries, sorted findings,
  evidence metadata, category-keyed recommendations, provenance appendix). No I/O.
- `report-html.ts` — **pure, deterministic** `renderReportHtml(model)`: a
  self-contained HTML document (inline print CSS, the 10 required sections). No
  `<script>`, no external URLs, every interpolated value HTML-escaped.
- `report-service.ts` — `getReport(actor, submissionId)`: branch-scoped Prisma reads
  (reusing the `branchScope`/`getReadable` pattern) → `buildReportModel` with a single
  `generatedAt` stamp. The only impure layer.
- `index.ts` — barrel.

UI + export:
- `components/report/audit-report.tsx` — on-screen render of the model (print CSS).
- `app/(app)/reports/[submissionId]/page.tsx` — the report view.
- `app/(app)/reports/[submissionId]/export/route.ts` — read-only
  `GET ?format=json|html` download.
- `app/(app)/reports/page.tsx` — replaced the placeholder with the actor's submission
  list linking to each report.

## Guarantees

- **Reproducible from stored evidence only** — the report path makes no live CRM call;
  it reads the frozen snapshot metadata + persisted findings. Re-running produces the
  same report.
- **Deterministic** — no `Date.now()`/`new Date()` in the pure renderers; the timestamp
  flows from `model.generatedAt` (set once in the service layer). Fixed-order key
  construction throughout → byte-identical HTML/JSON for the same input (verified by a
  determinism test).
- **Injection-safe** — every interpolated value is HTML-escaped; a `<script>`-in-a-name
  test confirms the escaping fires.
- **Branch-scoped** — `getReport` rejects a submission the actor may not read with
  `NotFoundError` (defense in depth at the service layer, negatively tested).

## Open product question (surfaced, not decided here)

Branch Managers currently cannot reach `/reports` at all: `reports:view` and
`ROUTE_ACCESS` are Auditor/Super-Admin only (pre-existing, unchanged by this milestone).
The service-layer branch scoping is nonetheless correct and tested — but whether BMs
should have UI access to their own branch's reports is a roadmap decision, deliberately
left to the product owner rather than changed inside this infrastructure milestone.

## Timeline note

`ReportModel.timeline` uses the submission's `auditDate` as the "Audit date" anchor
event (the report input carries no separate created timestamp) plus `submittedAt` and
per-snapshot `retrievedAt` events, sorted ascending. Honest labels; no fabricated
"created" time.
