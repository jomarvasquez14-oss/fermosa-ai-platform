## What shipped

### Phase 1 — Browser framework (real driver)

`services/browser/` restructured into `types/ · driver/ · drivers/{playwright,mock}/ ·
selectors/ · pages/ · session/ · navigation/ · policies/ · utils/` (public API preserved
through the barrel). The `BrowserDriver` interface grew from six methods to the full
surface (`launch/close/goto/goBack/reload/currentUrl/click/fill/select/waitFor/locator/
text/table/tables/screenshot/download/evaluate`). **`PlaywrightBrowserDriver`** is the
ONLY module importing Playwright (lazy `import()` inside `launch()`;
`serverExternalPackages` keeps it out of the Next bundle). It maps every failure at the
boundary: TimeoutError → `CRM_TIMEOUT`, net/crash → `CRM_UNAVAILABLE`, 401/403 →
`CRM_FORBIDDEN`. In-page table extraction travels as a source STRING (transpiler-injected
helpers like esbuild's `__name` do not exist inside the page — found by smoke test).

**`BrowserSessionManager`**: launch-on-demand, ONE login per execution (concurrent
callers share the in-flight attempt), cookie/context reuse in memory only, logout
detection, one-reconnect recovery, idle re-verification (`TimeoutPolicy.idleMs`).
**Policies**: `RetryPolicy`, `TimeoutPolicy`, `NavigationPolicy` (politeness lives in
the real driver), `FailurePolicy` — never retry captcha/403/401/layout drift; retry only
timeouts, disconnects, crashes.

**Selector map v1 is now REAL**: derived from the `docs/crm-reference/` captures
(2026-07-14 study) — actual form field names (`search`, `search_mobile`), table ids
(`#invoice-table`, `#activity-logs-table`), the treatment accordion, Bootstrap
pagination, the logout POST form. Structural fingerprints per page **plus per-table
column-header verification** (`headerIndexMap`) — a header mismatch throws
`LayoutChangedError` before one row is parsed. Each page entry also documents its
`neverInteract` list (delete/edit/create controls automation must never touch).

### Phase 2 — Page objects

`LoginPage` (captcha stop, provisional selectors — login was never captured),
`DashboardPage` (auth invariant + announcement-modal dismissal), `PatientsPage`
(search by the fields the CRM actually offers — name/mobile/last-visit; cid extracted
from the "View client" href; pagination; reset), `PatientProfilePage` (tab navigation,
demographics read from the CRM's own form values, lock-state read, READ-ONLY by
construction), `TreatmentTab` (accordion panels → package title `(x/y) completed` +
session rows hidden in readonly inputs/disabled selects; BRANCH option value = CRM
branch id), `InvoiceTab` (AJAX DataTable settle-wait; verbatim status literals; detail
view parsed structurally by classifying tables on their headers — services + multi-
payment installments incl. `RECEIVED BY "id name"`), `ActivityLogPage` (filtered GET,
nested Details/Old Details diff tables, page-capped retrieval — never a full scan).

### Phase 3 — PlaywrightCRMConnector

`services/crm/connectors/playwright/` implements the frozen contract: `healthCheck` /
`findPatients` / `fetchPatientRecord`. Credentials ONLY from `CRM_URL` / `CRM_USERNAME`
/ `CRM_PASSWORD` (validated on first use; `CRM_BROWSER_HEADLESS=false` for supervised
runs). `CRM_CONNECTOR=playwright` is an env alias for `browser-automation` — the
factory, record schema, and connector-kind enum are unchanged. Search semantics match
the mock: `found` / `not-found` / `ambiguous`, candidates never auto-picked; `crmId`
resolves by direct profile navigation; email refines client-side. `/dev/crm` works
against the real connector with zero changes; `/dev/browser` now shows the configured
connector and probes its health.

### Phase 4 — Normalization & validation

`normalizer.ts`: page output → `NormalizedCrmPatientRecord` (ADR-027, schema
untouched). Status literals mapped (`PARTIALLY PAID` → `partial`), money to decimal
strings, dates to ISO, activity diffs to `{field, oldValue, newValue}`. Every record
passes the Zod schema at the connector boundary; unparseable money/dates and schema
failures throw `CRM_LAYOUT` loudly — never silently wrong data. Provenance:
`retrievedAt`, `connectorKind: "browser-automation"`, `sourceRef =
"crm-selectors/v1 /clients/{cid}"`.

## Known limitations (documented, deliberate)

1. **Login selectors are provisional** — the login page was never captured
   (CRM_DISCOVERY §8 gating input). Minimal fingerprint fails loudly if wrong.
2. **Invoice payments are `null`** — the detail-view trigger lives in the CRM's
   `invoice.js` (not captured). Parsing is implemented and tested; retrieval is gated
   behind the `invoiceDetail` capability (v1: off).
3. **dob-only search returns `not-found`** — the live CRM has no dob filter (the
   captures' "rich search form" turned out to be the Register modal). Divergence from
   the mock, logged and documented.
4. **`performedBy.role` is always `"unknown"`** — USER-column semantics remain the §3
   open question; roles are never guessed.
5. **Activity keyword scoping** assumes the CRM's search matches patient names;
   confirm against the live system.
