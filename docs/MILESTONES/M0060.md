# M0060 — OCR Extraction + Calibration Harness

> Status: **Complete** (2026-07-15) · Branch: `feature/crm-browser-connector`
> The M0048 "ground-truth tool" realized as a CLI harness: run a provider over
> the 189 logbook images, store per-image results, and score them field-by-field
> against human ground truth with a confidence-calibration table. Part 2 of 2
> (M0059 built the v2 schema this consumes). Mock path needs no key; real
> calibration needs an Anthropic API key.

## What it adds

| Piece | What |
| --- | --- |
| **Scorer (pure)** | `services/ai/calibration/score.ts` — `scorePage(extraction, groundTruth)` + `aggregate()`. Transcription-tolerant compare (`normalizeValue`: trim/lowercase/collapse-spaces, numbers lose `₱`/commas). Per scalar field accuracy; services/meds item precision-recall (name **and** amount); entry match by `lineNumber`; confidence bucketed into the §5 bands (manual / highlight / auto). |
| **`ocr:extract`** | `scripts/ocr-extract.ts` — runs `getAIProvider()` (mock default; `AI_PROVIDER=claude` + `ANTHROPIC_API_KEY` for live) with prompt `v002` over `ocr-samples/branches/<branch>/`, writing `ocr-samples/results/<branch>/<base>.json` (extraction + usage + provider/model). `--branch`/`--all`/`--limit`/`--force`; resumable; running cost to stderr. |
| **`ocr:score`** | `scripts/ocr-score.ts` — pairs each `results/<branch>/<base>.json` with `expected/<base>.json`, prints per-field accuracy + service/med P/R + the calibration table, and writes `ocr-samples/results/_report.json`. |

## Verification

- **Unit:** `services/ai/calibration/score.test.ts` (5) — perfect transcription
  scores 100% incl. numeric normalization (`2,000` = `2000`), a wrong field is
  counted and bucketed by confidence, unmatched extracted lines are ignored, and
  `aggregate` sums pages. `pnpm typecheck`/`lint` green; full `pnpm release-check`.
- **End-to-end (mock, no key):** `ocr:extract --branch "Fermosa - Imus" --limit 3`
  read 3 real images and wrote schema-valid results; `ocr:score` paired the seed,
  printed the table, and wrote `_report.json`.
- **Real signal from the first run:** the seeded IMUS photo is a **summary page**
  (the daily rollup), and the mock hallucinated **5 transaction entries** on it
  (`0/0 expected (5 extracted)`) — precisely the false-positive calibration
  catches. It also confirmed a live-only need: many photos are summary pages, so
  `pageType` classification is a real accuracy axis.

## Ground-truth seed + convention

`ocr-samples/expected/<image-basename>.json` is the human transcription (bare
values, `_TEMPLATE.json` shows the shape; validate with `ocr:gt:check`). A first
seed was created for the IMUS summary photo (`pageType: "summary"`, no rows —
accurate and out-of-scope-safe). Transaction-page seeds and bulk transcription
are staff work; the harness is what turns them into calibration numbers.

## What's still external (unchanged blockers)

- **Anthropic API key** — not present locally, so no *live* extraction yet; the
  mock proves the mechanics only. With a key: `AI_PROVIDER=claude pnpm ocr:extract
  -- --branch "Fermosa - Imus" --limit 3` then `pnpm ocr:score` gives real yield.
- **No-retention API tier sign-off** (PII) before the first live call.
- Transaction-page ground truth for field-level accuracy (staff).

## Scope / contracts

No schema change (consumes M0059's v2), no DB change, no ADR. All images,
results, and transcriptions live under gitignored `ocr-samples/` (patient PII);
raw images are never logged. Consuming the richer fields in the CRM comparison
rules remains the explicit follow-on.
